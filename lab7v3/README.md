##  Опис структури

1. **`IEntity`**: Базовий інтерфейс із властивістю `int Id { get; set; }`.
2. **`Order`**: Сутність замовлення (`OrderDate`, `TotalAmount`, `CustomerId`), що 
реалізує `IEntity`.
3. **`IRepository<T>`**: Узагальнений інтерфейс з обмеженням `where T : class, IEntity` 
для CRUD-операцій (`GetById`, `GetAll`, `Add`, `Update`, `Delete`).
4. **`InMemoryRepository<T>`**: Реалізація `IRepository<T>` для зберігання об'єктів у
 списку `List<T>`.
5. **`lab12v3.Tests`**: Набір юніт-тестів на xUnit, які повністю покривають усі 
CRUD-операції, включаючи обробку неіснуючих елементів.
---
##  Відповіді на контрольні запитання

1. **Роль `where`-обмежень:** Гарантують, що узагальнений тип T  має потрібні 
властивості (наприклад, `IEntity` гарантує наявність поля `Id`).
2. **Переваги `IRepository`:** Абстрагує роботу з даними. Код вищого рівня не залежить
 від того, де зберігаються дані (у пам'яті, базі даних чи файлі).
3. **Важливість юніт-тестів для Generics:** Оскільки узагальнені компоненти працюють з 
різними типами, юніт-тести дозволяють переконатися, що логіка репозиторію працює 
стабільно та передбачувано.
4. **Generics vs `object`:** Generics забезпечують перевірку типів на етапі
 компіляції та працюють швидше без Boxing/Unboxing.
